# COMPLETE LOGIC FOR GLOBAL E-COMMERCE SYNTHETIC DATASET

## SYSTEM OVERVIEW

The dataset simulates a real global e-commerce company with complete business logic, regional authenticity, and data integrity. All constraints are enforced with zero exceptions. The system generates 12 interconnected tables with realistic distributions, seasonality patterns, and business rules.

The entire dataset is generated using Python with pandas, numpy, faker, and random libraries. All random processes are seeded for reproducibility.

Time Range: January 2022 to March 2026
Currency: USD (all prices final, tax-inclusive, no tax fields)
Language: English only

Excluded Regions: Asia and all Arab countries
Included Regions: North America, South America, Europe, Oceania, Africa (non-Arab countries only)

Purpose: Create a complete calendar covering the entire data period.

Logic:

- Total days: 1,550 days
- Each day has a unique date_id in YYYYMMDD format

## TABLE 9: ORDER ITEMS LOGIC

Purpose: Create approximately 20,000 order items linking products to orders with pricing and shipping logic.

Logic:
- Each order has 1 to 4 items (average 2 items)
- Total items approximately 20,000
- Each item links one product to one order
- Each item has one seller

Product skew (80/20 rule):
20% of products generate 80% of sales
When selecting a product for an order item, there is an 80% chance to select from the top 20% of products

Seller skew (80/20 rule):
20% of sellers (Gold tier) generate 70% of revenue
When selecting a seller for an order item, there is a 70% chance to select a Gold seller

Quantity per item: 1 to 3 units
unit_price: equals product_price at order time
cogs: equals product_cost
freight_value: calculated based on product dimensions and category

Freight value calculation formula:
freight = base_freight + (weight_kg x weight_factor) + (volume_liters x volume_factor)

## TABLE 10: PAYMENTS LOGIC

Purpose: Record payment information linked to orders.

Logic:
- One payment record per order
- payment_date: within 0-48 hours of order_purchase_timestamp

Payment type distribution:
Card: 50%
PayPal: 20%
COD (Cash on Delivery): 20%
Other: 10%

Payment status mapping:
If order_status is delivered or shipped: payment_status = 'success'
If order_status is canceled: payment_status = 'failed'
If order_status is returned: payment_status randomly 'success' (40%) or 'refunded' (60%)

Payment value calculation:
payment_value = (unit_price x quantity) + freight_value - discount_value

Output columns:
payment_id (PK), order_id (FK), payment_type, payment_value, payment_status, payment_date

## TABLE 11: DELIVERY LOGIC

Purpose: Record shipping and delivery information with no NULL dates.

Logic:
- One delivery record per order
- All dates are populated (no NULLs) - estimated dates are used for non-delivered orders

Timeline:
order_approved_at -> +1-3 days -> order_delivered_carrier_date
order_delivered_carrier_date -> +5-14 days -> order_estimated_delivery_date
order_delivered_carrier_date -> +2-9 days -> order_delivered_customer_date (for delivered orders)

Shipping providers by region:
North America: FedEx, UPS, USPS
Europe: DHL, local carrier
South America, Africa, Oceania: local carrier

Delivery status by order status:
For delivered orders: on_time (delay <= 0 days), late (delay 1-3 days), very_late (delay > 3 days)
For shipped orders: estimated_on_time, estimated_late, estimated_very_late
For canceled orders: canceled
For returned orders: returned_on_time, returned_late, returned_very_late

delay_days calculation:
delay_days = order_delivered_customer_date - order_estimated_delivery_date

Output columns:
order_id (PK, FK), order_delivered_carrier_date, order_delivered_customer_date, order_estimated_delivery_date, shipping_provider, delay_days, delivery_status
